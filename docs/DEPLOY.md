# Deploy for free (no credit card)

Two free services: **TiDB Cloud Starter** for the MySQL-compatible database and **Render** for the Node.js service. You create the accounts and type the secrets yourself in their dashboards; nothing secret goes in this repository or in a chat.

Terms checked in November 2026 (they can change, check the pricing pages before relying on them):

| Service             | Free plan                                                                                                                        | Things to know                                                                                                                                                                                                                                  |
| ------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Render, web service | 750 instance hours per calendar month, no credit card, TLS and environment variables included                                    | Spins down after 15 minutes without traffic; the next visit takes about a minute to wake it. The filesystem is ephemeral (the app stores nothing on disk). Free services stop for the rest of the month if the bandwidth allowance is exceeded. |
| TiDB Cloud Starter  | 5 GiB row storage and 50 million request units per month per instance, no credit card for the first five instances, TLS required | Beyond the free quota the instance is throttled until the next month.                                                                                                                                                                           |

Not used: Aiven stopped offering a free MySQL plan (its page says the MySQL free tier is retired), and Render's free database is PostgreSQL that expires after 30 days.

The app has been tested on MySQL 8 and MariaDB. It has **not** yet been run against TiDB: if the first deployment shows a database error in the Render logs, please report it.

## 1. Create the database (TiDB Cloud Starter)

Screen labels may differ slightly from these names.

1. Go to tidbcloud.com and sign up (Google, GitHub or e-mail).
2. Create a **Starter** instance. Pick the **Frankfurt (eu-central-1)** region (closest to the Render service below).
3. When the password is generated, **copy it into a password manager**. It is shown only once.
4. Open the instance and click **Connect**. Note the **host**, the **port** (4000), the **user name** (it starts with a prefix, for example `abc123.root`) and keep the page open.
5. If an IP access list is shown, allow access from anywhere (Render's free plan has no fixed IP address).
6. Open the SQL editor and run: `CREATE DATABASE industriel_minier;`

The tables are created automatically when the service starts (`npm run migrate` runs inside the start command).

## 2. Create the service (Render)

1. Go to render.com and sign up with GitHub (no card needed).
2. Click **New** then **Blueprint**, authorize Render to read the `projet-im` repository, select it and choose the `main` branch.
3. Render reads `render.yaml` and asks for four values. Enter:
   - `DB_HOST`: the TiDB host from step 1.4
   - `DB_USER`: the TiDB user name (with its prefix)
   - `DB_PASSWORD`: the password you saved
   - `DB_NAME`: `industriel_minier`
4. Click **Apply**. `JWT_SECRET` is generated by Render. Wait for the first deploy to finish (a few minutes).
5. Open the service URL (`https://projet-im-....onrender.com`). Check `/healthz` answers `{"status":"ok"}`, then sign in with the demo account from the README.
6. Put the URL in the README (the "Live demo" line).

`DEMO_MODE` is on in the blueprint: the whole database is replaced by fictional data every time the service starts and every 6 hours. **Never point a demo service at a database that holds real data.**

## 3. Optional: real sign-up

Sign-up needs an SMTP server to e-mail verification codes. Add `SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD` and `SMTP_FROM` in the Render dashboard (Environment). Without them sign-up is disabled, which is what you want for a public demo. Not verified: whether Render's free plan allows outbound SMTP connections.

## Run it as your own (non-demo) instance

Set `DEMO_MODE=false`, use a different database, create the first account through sign-up (with SMTP configured), and set `ALLOWED_ORIGIN` only if another website must call the API.
